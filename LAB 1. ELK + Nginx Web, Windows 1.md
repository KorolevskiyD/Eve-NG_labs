В текущей конфигурации, в ELK имеются логи только контейнеров ELK, но не веб-сервера Nginx.

Служба `filebeat` запущена, но еще необходимо выполнить `filebeat setup`. Данная команда загружает компоненты: шаблоны индексов, политики ILM, информационные панели Kibana.
При выполнении команды, получаем ошибку
```
root@debianWeb:/home/userweb# filebeat setup
Exiting: couldn't connect to any of the configured Elasticsearch hosts. Errors: [error connecting to Elasticsearch at https://192.168.10.129:9200: Get "https://192.168.10.129:9200": x509: certificate signed by unknown authority]
```
Отключим проверку SSL-сертификата, внеся изменение в `/etc/filebeat/filebeat.yml`.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123427226.png)

Аналогично укажем адрес Kibana и авторизационные данные.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123427244.png)

Логи контейнера хранятся в каталоге `/var/lib/docker/containers/*.log`. Предварительно выполнив несколько запросов к веб-сайту просмотрим содержимое.

### Задание 4. Неправомерные действия
С помощью gobuster выполним перебор 5000 каталогов сайта.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428096.png)

Обратимся к ELK и просмотрим результат.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428139.png)

Все запросы, кроме одного вернулись с ошибкой 404.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428246.png)

На самой машине злоумышленника мониторинг не установлен, но как и подобает сканерам, они возвращаюсь свой UA.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428290.png)

Аналогично выполним запуск `dirb`.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428321.png)

Использование `dirb` соответствует другому UA. Быстрый поиск по UA встречается в статьях про атаки в обслуживании ([например](https://www.research-lab.ca/2014/06/http-ddos-mozilla4-0-compatible-msie-6-0-windows-nt-5-1-sv1/)).
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428355.png)

Создадим правило. Для этого переходим в `Alerts` в разделе `Security`. И выбираем `Manage rules`.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428392.png)

Далее нажимаем `Create new rule`.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428420.png)

Тип правила - `threshold`. Данный тип сгенерирует алерт при пересечении заданного порога.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428444.png)

Первое правило на сканирование директорий.
Правило будет простым, при появлении более 75 раз ошибки 404 - алертим. Группируем все по IP-адресу источника.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428492.png)

Далее указываем наименование и описание. Тут же можно указать критичность, оставляю по умолчанию.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428527.png)

Расписание запуска правила указываем 5 минут.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428553.png)

Также уведомляем при каждом запуске.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428579.png)

Правило создано, теперь необходимо ожидать 5 минут для его следующего выполнения.
![](LAB%201.%20ELK%20+%20Nginx%20Web,%20Windows%201/IMG-20260720123428609.png)

После выполнения правила был создан алерт, то есть, перебор директорий был зафиксирован.
